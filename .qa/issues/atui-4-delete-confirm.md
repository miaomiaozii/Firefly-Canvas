# 【Agent TUI】节点一键删除无确认（焦点在卡内按钮时 Delete 键也会删节点）

验证人：QA（Tabbit 实操中**真实触发**：单击误删整个节点，含全部对话历史，Ctrl+Z 恢复，2026-11-13）。严重度 S1。

## 发生了什么
QA 实测中单击节点框右上角区域，整个 Agent 节点瞬间消失，无任何确认弹窗。该位置是悬停才出现的删除按钮（节点右上角，紧贴卡片头部边缘）。另外：卡片内部按钮获得焦点后按 Delete 键也会直接删除节点（键盘可直达的破坏性操作）。

## 我期望看到什么
破坏性操作有确认步骤，或至少不在贴手可及的位置一键触发；焦点在卡片内部时 Delete 不应删节点。

## 复现步骤
1. 悬停 Agent 节点 → 右上角出现 × 按钮 → 单击 → 节点瞬间消失（无确认）
2. 点击卡片内任一按钮（如回退）使其获得焦点 → 按 Delete → 节点被删

## 补充信息
- 删除按钮：static/js/smart-canvas.js:9228（悬停动作条，css:460-461 右上角 z-8）→ static/js/canvas-node-ops.js:313-319 `deleteNodeFromButton` → `deleteNode` 无确认。无确认是 #149 B5 的既定设计（代码注释可查），但 Agent 节点承载完整对话历史，破坏成本远高于普通节点——建议产品决策：Agent 节点特例加确认，或删除前自动快照可恢复。
- 键盘泄漏：可编辑目标判定不含按钮（isEditableTarget），按钮聚焦时 Delete 冒泡成画布删除。
- QA 事故记录：误删已用 Ctrl+Z 恢复，画布已验证还原原状（节点 12 个、尺寸 806x650、草稿已清）。
