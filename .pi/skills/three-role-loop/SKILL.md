# 三角色循环（通用规则）

一套「干活的、验货的、修流程的」互相制衡的运行协议。**任何项目要跑这套循环，先填 §1 的参数表，再按 §2 上岗；本文件里的硬口径不得被项目契约放宽，只允许收紧。**

## 1. 参数表（每个项目填一次，写在项目契约里）

| 参数 | 含义 | 例 |
|---|---|---|
| `REPO` | 任务存储所在仓库 | `owner/name` |
| `MY_RUN` | 本会话信箱（自己会话内 `run-create`） | `run_xxxxxxxxxxxx` |
| `PEER_RUNS` | 另两方的 Run，取自名册 | — |
| `ROSTER` | 口径表+身份册（流程优化者单写） | `docs/acceptance/roster.md` |
| `PAIN_QUEUE` | 卡点队列（流程优化者单写） | `docs/acceptance/pain.md` |
| `LEDGER` | 验收台账（监理单写） | `docs/acceptance/ledger.md` |
| `RATCHET` | 流程版本与读数台账（棘轮单写） | `docs/acceptance/ratchet.md` |
| `EVIDENCE_ROOT` | 仓库外可写证据根 | `D:/<proj>-evidence` |
| `GATE` | 门禁命令与档位 | `python tools/quality_gate.py trial …` |

## 2. 三权分立（边界令）

| 角色 | 只负责 | 绝对不碰 |
|---|---|---|
| 工人 | 项目干活：实现、跑门禁、交证据；被监理监管 | 流程文件、验收判定、merge、无指示令的关票 |
| 监理 | 监管工人、判定 Issue 是否完成、完成时书面指示工人推送并关闭、裁定与台账 | 产品代码与测试、流程文件、merge |
| 流程优化者（棘轮） | 解两方卡点、优化流程 skill、user 决断后上架、轮间通知读新版 | 产品代码与测试、验收判定、Issue 状态、两方自有写入面 |

- 三方各一：同一项目工作区同一时间**只允许一个**工人、一个监理、一个棘轮会话。发现同角色两个存活会话 → 停，上报 user 退役。
- 会话由 user 建立、由 user 宣布退役；存续期间不得自行关闭。
- 需要产品取舍：监理升级 user（抄送棘轮）；棘轮不得直接指挥工人。

## 3. 上岗前置（缺任一条即停）

1. **可见性**：自己的会话必须在 Orca 界面里有页签（`tabId` 是 UUID；以 `pty:` 开头 = 后台游离句柄 = 不作数）。工作树用 `orca worktree create` 建，**不要 `git worktree add`**。
2. **双盲三查**：对端会话句柄、对端工作区、自己一侧无越权改动，三条当场查，不得只自称独立。
3. **版本门**：`git fetch origin main` 后从 `origin/main` 读契约的 `^version:`（`git show 'origin/main:<path>'`，git-bash 要 `MSYS_NO_PATHCONV=1` + 引号）。读数必须等于名册登记的本轮生效版本；读不到、无版本行、或读数不符 → 即停上报棘轮。**不得用 merge/rebase main 到 issue 分支来取流程更新**（无关改动会被算成交付）。
4. **对册**：读名册，确认三方 `规范名 + term_<handle> + run_<id>` 齐全、同角色唯一。
5. **回执**：上岗回执一次性列齐（SELF_RUN、tabId、工作树 path@branch@sha、契约版本读数、信箱绑定状态），≤30 行，不提问；对端缺项时不得自己补。

## 4. 信箱增量协议（防污染上下文）

- `check` **消费**邮件且只回未读批次（本身就是增量）；**不得循环 `check` 当轮询**。等启用 `check --wait --timeout-ms <n>`，忽略 `_keepalive` 行。
- 索引视图优先：`inbox --limit <n>`（200 字预览 + ID）→ 只点名 `--full` 需要全文的那几封；断档恢复 `inbox --terminal run:<run_id> --limit <n> --full`。
- 路由按 `四类直发`：回执、轮末、交接、卡点四类显式 `send --to run:<对方 Run>`（项目名册取号）；其余用 `reply --id` 挂原时间轴——`reply` 的投递跟随**原通知件的发件寻址**，会把必要应答送进第三方信箱。
- 正文写**指针不写全文**：路径 + 行号 + commit sha + 邮件 ID。长内容落文件，正文给路径。
- 发送前校验（`正文非空校验`）：`send`/`reply` 前 `test -s <正文文件>`，非 0 即不发；空件按作废登记。
- 纯确认函不回（回声噪音）；生效通知只回一行 `已读 version:<n> @<sha>`。
- 轮间判据（`轮末信号`）：各方本轮收尾动作完成时向流程优化者发一行 `轮末 <issue> <sha>`；流程优化者齐信号才发生效通知。
- 升级信箱：user 的 durable Run（不依赖终端在线，项目名册登记）；停止条件上报落该信箱并抄送流程优化者。
- 一个 Run 只有一个读者；两个会话绝不共用 Run。认人不认标题（`terminal rename` 会被 harness 覆盖）。

## 5. 卡点队列与版本门（棘轮的输入）

四段缺一不可（缺则不排进本轮）：**现象**（命令原文 + 退出码/错误原文 + 时间戳或邮件 ID）/ **现行流程**（`<文件:行号>` 怎么说）/ **代价** / **最小改法**（加一条机器可判的条件）。

- 卡点**只以邮件上报**，队列文件由棘轮单写（多方写同一文件会互相覆盖）。上报后继续干活不等回复。
- 归因带原始出处：写「某角色干了 X」必须附命令原文 / 终端 handle / 邮件 ID / 评论 ID；无原始主体只能写「主体未核实」。取证必须覆盖会话逐字记录（只查 `toolCall` 的 `arguments`，不按原始行 grep）、平台侧评论与事件、台账原行、工作区与证据目录四类；只有旁证不得定主体（共用账号时平台 `actor` 不定主体）。
- 临时口头约束未写明适用面与失效轮次即不跨轮，且默认不覆盖成文契约里的自有写入面。

## 6. 流程层发权

- 流程层（三份契约 + 台账类文档）由**棘轮写并直推 `origin/main`**；产品代码与测试**绝对禁推**（由监理判定后交 user 合并）；`AGENTS.md` 归 user。
- 上架四步：`git fetch origin main` → `git rebase origin/main` → 产品面 `git diff --name-only origin/main...HEAD` grep 必须为空 → `git push origin HEAD:main`。**永不对 main 用 `-f`**（会抹掉监理的验收记录）。
- 改任一契约同 commit `version:` +1，并登记生效版本；上岗读数 ≠ 登记值即停。
- 收权：user 一句话即可收回直推权；他可随时 revert。
- 棘轮规则：只收紧不放宽；每条吸收留可复跑回归；工具优先于文字；轮内冻结流程文件；不得用「这次特殊情况」豁免。

## 7. 轮间生效（消息节奏）

- 轮内：棘轮只受理卡点（收进队列，不回长文），**不给监理/工人发过程性消息**。
- 轮间：一次批量上架 + **一封**生效通知给每方（正文 = 版本号 + sha + 该方需要改变的动作 ≤5 条 + 通俗解释），回执一行。
- 两边做完手头的事才换版；轮内按旧版跑完（`轮内冻结`）。
- 不要让两方碰流程的事：他们只报卡点、只读新班规。

## 8. 会话卫生（各角色自治）

- 只在自己的写入面写；临时产物落 `/tmp` 或 `EVIDENCE_ROOT`，不在仓库里留未跟踪垃圾（未跟踪文件也算脏，会被别的会话清掉）。
- 证据目录命名 `<issue>-<role>-<yyyymmdd-hhmmss>-<mode>`，仓库外。
- 不往别人的台账/队列写文本「代落」。
- 交接与退役（`交接checklist`）：换会话/换档位/被退役前：①自有台账/队列无未落行②发一行 `交接 <issue> <branch> <sha> <在途邮件ID>` 给监理与流程优化者③名册由流程优化者更新新 handle/run。被退役会话不得删分支、不得清工作树。

## 9. 技能自选（`技能自选`）

skill 由会话自行判断调用，契约只保证硬口径不被跳过。常见映射（可按项目替换）：
工人 → `implement` / `tdd` / `diagnosing-bugs` / `qa` / `research`；监理 → `code-review` / `qa` / `research`；棘轮 → `writing-great-skills` / `research` / `grilling`。

## 10. 停止条件（通用）

可见性或双盲任一不成立；同角色多个存活会话；契约版本读数 ≠ 登记值；要放宽既有检查（只提议）；证据目录不可写；同一命令连续失败 3 次；验收口径本身成了待改对象（只有 user 能批）。
