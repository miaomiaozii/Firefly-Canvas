# batch-6 任务卡：#143 并行 Agent（多节点并发执行）

## 背景
多个 Agent 节点已隔离（每节点 = 独立会话 + 独立 pi 子进程 + 项目作用域工具，#117 M3 完成），但**并行执行未验证**：多个 Agent 同时操作同一画布时，画布变更串行化、并行生成任务共存、各节点 TUI 事件流是否串扰，均未测试。本批次让多 Agent 并行成为受支持的产品行为：以**并发行为验证 + 修复发现的问题**为主，不重写架构。

## 范围
1. **并发行为验证（核心）**：写测试证明/发现以下行为，修复发现的问题：
   - 多个 Agent 节点可同时运行任务（各自独立子进程，互不阻塞）
   - 并发画布变更经既有画布 revision 机制串行化，互不破坏（revision 单调递增、无丢失）
   - 多 Agent 并行触发的生成任务照常共存（任务状态卡、生成历史各归其位，不串）
   - 各节点 TUI 事件流互不串扰（A 节点的消息/工具/确认不泄漏到 B 节点）
2. **并发上限**：复用既有生成管线限制，不加 Agent 专属限制。若发现无上限导致的资源问题，记录并加合理上限（非本批次强制）。
3. **死锁/饿死场景**：若发现，先加超时 + 错误态呈现，不静默排队。
4. **多节点 TUI 渲染**：验证画布上同时存在多个运行中 Agent 节点时，各节点 TUI 状态/消息/确认独立正确。

## 关键机制（侦察所得）
- 会话隔离：`agent_host_manager.sessions` key = `f"{project_id}:{node_id}"`，每节点独立 AgentSession + 独立 pi 子进程
- 画布 revision/串行化：既有机制（查 canvas 保存/revision 相关代码，确认并发写入如何串行化）
- 生成任务：既有生成管线（任务状态卡、生成历史），查其并发行为
- TUI 事件流：每节点独立 WebSocket（agent_event_stream），查事件路由是否按 node_id 隔离

## 约束
- 基于 M3 多节点隔离，不重写架构
- 画布变更走既有 revision/串行化，不加新锁（除非发现既有机制有并发 bug，则修复并说明）
- 不加 Agent 间通信/协调（Out of Scope）
- 不加全局调度/优先级（Out of Scope）
