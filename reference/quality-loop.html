质量闭环速查

发现 bug 的目的，不只是让这一次变绿，而是让同一类错误以后无法静默回来。

用户旅程

由红变绿 质量门禁

测试放哪一层

问题优先测试层Firefly Canvas 例子
纯参数映射单元/矩阵测试Banana 2K 选择是否映射到 -2k
模块边界协议集成/假 HTTP最终 multipart 是否含两张有序参考图
浏览器交互少量浏览器测试尺寸控件是否真的写入项目请求
真实配置漂移只读运行时探针线上模型能力是否与版本化配置一致

每个 bug 的完成定义

  1. 有一个已经运行过、能稳定捕获原症状的命令。
  2. 回归测试位于最小且真实的调用边界。
  3. 修复后，原始复现和最小测试都通过。
  4. 相关参数合同被写成测试，不再靠记忆。
  5. 测试进入日常质量门禁，而不是留在聊天记录里。

不要这样做

  • 看见视觉结果不对就直接猜 CSS 或 provider。
  • 只增加一个巨大端到端测试，失败后再全仓库找原因。
  • 为让测试变绿而删除正确的参数断言。
  • 修完后不记录协议来源，几天后再次“整理”掉关键字段。
  • 让用户承担完整的探索性测试工作。
