# #493 existing history, deleted result node

Approved interpretation: deleting a result node does not delete its retained generation history. Retrieval may complete that original history, but must not create any node, turn, paid attempt or generation request.

- Canonical history retains `download_generation` and immutable `result_download_slots` (item ID, original index and output ID). A missing node requires the durable history generation; a present node additionally requires its original pending task. Missing history, cancelled/terminal-invalid status, mismatched generation/slot and unproven Agent journal ancestry fail closed before the download or media import. Old history-only records without generation evidence fail closed; no identity is synthesized.
- New queues bind `invocation_identity` to the actual invocation-only Soon provider/auth view while preserving the original provider/config and selected-model identity guards. Recovery checks those original guards first, independently recomputes invocation identity, then GETs the original task using the matching invocation auth. Legacy queues retain selected-model behavior only when that profile is unchanged; ambiguous legacy automatic-profile records fail before GET with `无法核验原生成请求身份，不能安全取回；不会重新生成`. No auth guess or generation fallback is permitted.
- History-only publication merges retained canonical outputs and preserves provenance and occurrence-deletion tombstones. Existing nodes continue through normal generation completion. The private queue remains server-owned; callers can select only item IDs, never submit a URL or provenance.
- `Group.node_exists` is a boolean. False means the history/project surfaces remain available, but locating or rendering a result node must not recreate it. Completed history GET computes it from the current canvas.
- An Agent task whose generated result failed download returns `status: download_failed`, `failure.code: RESULT_DOWNLOAD_FAILED` and, only after queue/journal validation, `retrieval.type: image_result_retrieval`. Retrieval carries the public Group plus original `op_id`, original `turn_id`, `generates: false`, `additional_cost: false`. The wait endpoint treats this as a terminal generation outcome, not a timeout or an instruction to resubmit.
- Retrieval writes use original operation ancestry and turn. Canvas deltas are child journal records, not another generation or turn. Recovery releases all settled family guards for this task token, not tokens of other batch tasks. A writer resolved before undo rechecks the original operation under the store lock before writing.
- Real undo is conflict-aware: normal recovered canvas outputs revert through `/ops/undo`; a user-deleted result node makes that original canvas delta conflict. The safe 409 does not resurrect it or erase history. History-only media/history are retained, not represented as a newly invented canvas delta.
