## 2. 架构终态（W1 拆分完成，main.py 21698→1680 行，-92%）

```
main.py                     装配层：FastAPI app + lifespan + include_router(41) + __main__ 守卫
app/
  core.py                   5999 行：imports + 全局状态 + 共享函数层（MAIN_SYNCED 常量/锁/FUTURES）
  constants.py              纯常量（BASE_DIR 等）
  routers/                  41 个域模块（api_project_library 2244 行 / api_chat / api_providers ...）
  services/                 14 个业务模块（providers/generation/media/agents/conversation 等）
    _base.py                动态绑定机制：_main(name) 运行时查 main 模块属性（测试 patch 生效）
  data/                     运行时 JSON（gitignore）
firefly_generation.py       模型路由（route_image/video_generation、image_size、协议适配）
firefly_projects.py         ProjectStore（乐观锁 RevisionConflict、媒体引用一致性）
```

关键机制（新对话必须理解）：
- `_app_main` 惰性解析：`FIREFLY_MAIN_MODULE` 环境变量 → sys.modules['main'] → '__main__' 兜底；router 绑定行 + core `_app_main()` 函数。测试隔离 exec 依赖此机制。
- `services/_base.py`：`_main('X')` 运行时从 main 模块取属性（含 `_main_bound_module` 优先级）→ 测试 `patch.object(main, X)` 生效。
- 前端无 window.canvas（模块级 let），浏览器测试断言必须 `eval('canvas')`。
