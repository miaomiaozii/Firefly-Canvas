# 生成输出项拥有独立身份

一次生成记录可以包含多个有序的生成输出项，并且不同输出项可以共享同一个生成原件。用户执行“删除当前原图”时，系统按稳定的输出项身份只删除当前项及其在对应结果节点中的投影；不能用数组下标或生成原件标识代替输出项身份，也不能影响其他输出项、其他生成记录或已经完成的下游结果。只有当项目中不再存在对生成原件的任何引用时，媒体文件才从活动媒体区移入项目回收区。

## Consequences

- 每个生成输出项持有稳定且不可变的 `output_id` 与 `output_order`；历史记录和对应结果节点共享同一 `output_id`。
- 删除请求必须同时提交生成记录、输出项、当前位置和生成原件身份；任何缺失或错配都拒绝整个事务，不得回退为按原件标识批量删除。`/original/delete` 与 `/original/restore` 只接受完整输出项身份；项目范围删除/恢复使用显式命名的独立操作。
- 每次删除生成唯一的 `deletion_id`；恢复按该身份精确恢复一个输出项，不能只按生成原件标识猜测。
- 仍被其他输出项或项目内容引用的生成原件继续留在活动媒体区；逻辑删除项仍进入七天可恢复记录。
- “项目范围删除生成原件”保留为独立破坏性操作：它移除该原件的全部直接引用并把最后一份媒体文件移入回收区，不能与“删除当前原图”共用含糊的界面动作。
