# 保留在线多媒体生成并移除本地运行时

萤火画布保留在线图片生成、在线视频创作以及相关的多模态参考输入，但不再保留 ComfyUI、本地模型运行或工作流执行能力。相比继续兼容原项目的本地生成体系，项目把维护投入集中到在线模型路由、参考素材、局部编辑、视频创作、历史复用和 Photoshop 联动。

## Consequences

- 删除 ComfyUI 设置入口、连接逻辑、工作流导入执行、内置工作流和相关专用页面。
- 不把 Z-Image、Klein 或细节增强功能迁入核心画布；细节增强作为独立能力整体删除。
- 保留在线视频生成、视频参考、音频参考、视频预览和抽帧能力。
- 音频只作为多模态参考或视频音轨存在，暂不建设独立音频生成、剪辑或音频工程界面。
- 新的生成能力必须通过在线服务商接入，并遵守统一的生成请求和结果模型；允许直接 HTTP 接口或服务商 CLI 适配器。
- CLI 适配器可以保留，前提是模型推理发生在远程服务中，且不引入本地模型或工作流运行时。
- 删除前需先确认代码、测试和用户项目中不存在必须保留的 ComfyUI 数据。

## 修订（2026-11-15，issue #373）

**修订点：把「不再保留 ComfyUI」收窄为「不内置 ComfyUI」——允许以 API 方式接入用户自托管的 ComfyUI 服务。**

原因：这条判断与实际用法已经不一致。维护者当前在用本机 ComfyUI 出图（`comfyui-h3-image` 等多次提交），协议 `comfyui` 由 ADR 0025（2026-11-14）正式接入，设置页服务商卡片里也有对应的协议选项。ADR 0004 原文保留不删，因为它当时的历史判断（删掉内置工作流、内置工作流页面、专用设置入口、本地模型运行时）确实成立过，也确实执行过。

仍然成立的部分（一字未改）：
- 核心画布不内置模型运行时，也不内置工作流执行。ComfyUI 工作流由用户自己那份服务持有，应用只当客户端。
- 不引入本地模型权重、不打包 ComfyUI 本体、不代用户安装或启动它。
- 生成能力仍然统一走服务商抽象（请求体/响应/失败判定在适配器里），ADR 0006 的路由约束同样适用于 `comfyui`。
- 不恢复专用的 ComfyUI 设置页（`static/comfyui-settings.html` 仍不存在，由 `tests/test_global_settings.py` 钉住）。ComfyUI 只是协议下拉里的一个选项，配置面与其他协议同一张卡片。
- 「不把 Z-Image、Klein 或细节增强迁入核心画布」不变。

被修订的部分：原文「不再保留 ComfyUI」不再读作禁止接入任何 ComfyUI 端点；正确读法是「不保留内置的 ComfyUI 运行时与工作流引擎」。文案层面的守卫相应放宽：`comfyui` 字样只允许出现在协议下拉的选项里，渗进别的界面文案仍判红（口径写在该守卫的注释里）。
