# Photoshop 返回结果始终创建新节点

核心画布与 Photoshop 的往返采用非破坏式语义：发送到 Photoshop 的项目媒体保持不变，Photoshop 返回的图层、选区或合成结果保存为新的项目媒体原件，并在当前项目画布创建与发送源关联的 PS 编辑结果节点。

## Consequences

- Photoshop 插件必须绑定当前明确打开的项目，禁止写入全局素材目录。
- 多次返回产生多个可追溯结果，不覆盖之前版本。
- 插件通信必须携带项目、源节点和请求标识，避免结果落入错误项目或错误节点。
- 当前插件的可靠性问题需要作为独立改造范围处理，不能与画布界面删除混在同一个实现任务中。
- 现有资产库型插件作为旧版参考，不继续增量修补；新插件重做为“萤火画布 PS 连接器”。
- 新插件只负责连接状态、接收画布图片、发送当前图层或选区或合成图，以及展示往返任务状态。
- 插件内的独立生成、Agent、ComfyUI 和全局资产管理界面全部删除。
- 第一阶段只允许连接同一台电脑的 `127.0.0.1`，本机连接免验证并可自动恢复；局域网远程连接默认关闭，未来若启用必须另行设计配对机制。

## Validated round-trip contract

- 第一阶段继续使用仅监听 `127.0.0.1` 的免鉴权连接，但每次往返必须精确绑定
  `project_id`、`source_node_id` 和一次性的 `request_id`。
- 请求在服务端保存明确的创建与过期时间。返回只允许从 `pending` 转为一次
  `returned`；到期请求和已消费请求都是终态，不得再次写入项目。
- 服务端在任何项目写入前依次校验请求存在、三标识绑定、时效、来源节点和媒体
  完整性。失败使用稳定错误码并保持项目节点、连线和媒体不变。
- 返回文件名只作为显示信息。项目相对路径、媒体 ID、结果节点 ID 和来源边 ID
  全部由服务端生成；原型的所有成功路径都位于绑定项目目录内，路径穿越名在项目
  状态变更前被拒绝。
- 一次成功返回保存新的项目媒体原件、创建新的 PS 编辑结果节点、添加从发送源到
  结果的 `derived_from` 连线，并消费请求；绝不覆盖发送源。
- 并发请求相互独立，允许任意顺序返回。精简字段、状态机和稳定错误码见
  [`photoshop-round-trip-v1.md`](../protocols/photoshop-round-trip-v1.md)。

后自动退出。合法成功与两个逆序并发返回准确产生 3 组新媒体、PS 编辑结果节点和
来源边；源节点及原媒体哈希保持不变。错误项目、错误源节点、过期请求、重复返回、
路径穿越名、媒体哈希不符和未知请求均以确定错误码拒绝，错误项目保持零写入。
重复运行的 `results.json` SHA-256 相同，Standards 与 Spec 双轴审查均为
0 findings。

该证据接受的是上述协议与状态约束，不是原型实现。正式连接器仍须重写，并只保留
“发送到 PS / 从 PS 返回”、连接状态和往返任务状态。原型没有执行写盘中断或故障
注入，因此崩溃安全的原子持久化与回滚仍属于正式实现及其行为测试，不属于本次
已验证结论。正式实现还必须把最终路径 containment 校验前移到项目状态变更之前。
