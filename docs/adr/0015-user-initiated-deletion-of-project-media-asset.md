# 用户主动删除资源库媒体采用硬删除 + 引用清理

用户在资源库中主动删除某个项目媒体时，系统**硬删除**该媒体文件（不进入删除媒体回收区），并在同一事务内移除项目内对该媒体的全部直接引用（节点 images/资产字段、历史 inputs/outputs），为受影响的节点和历史记录写入对应的墓碑标记（`deletedInputTombstones` / `deletedOutputTombstones` / `deletedReferenceTombstones`），使界面可以显示“上游素材已删除”状态。删除前必须先通过引用检查端点向用户展示引用该媒体的全部节点，由用户确认后才执行。

## 与 ADR 0014 的边界

- “删除当前原图”（生成结果）仍走 ADR 0014 的独立流程：按输出项身份删除、保留 7 天可恢复记录、媒体移入回收区。
- 本 ADR 针对**资源库维度的用户主动删除**（任意来源的媒体，包括生成结果）。两个动作是不同意图，不得共用含糊的界面动作；资源库删除是终态操作，不提供撤销。
- 若生成任务正在引用目标媒体，删除被拒绝（409），需等待任务完成。

## 为什么硬删除而不是进回收区

- 用户诉求（Issue 背景）：资源库没有有效删除机制，无用素材越积越多；而生成原图回收区在界面上没有查看/恢复入口（“回收站机制不明朗”），把资源库删除也塞进去只会扩大一个没有出口的区。
- 回收区入口 + 批量清理作为独立后续 Issue 处理；在此之前，资源库删除保持可预期的“删掉就是删掉”语义。

## Consequences

- `DELETE /api/project-library/{project_id}/media/{asset_id}` 接受可选 `base_revision`；画布版本冲突返回 409 并携带最新画布，前端据此同步状态后提示重试。
- 删除成功后广播画布更新（`broadcast_canvas_updated`），其他窗口自动同步；前端用响应中的最新画布刷新本地 `nodes`，避免下次保存回写已清理的旧引用。
- 引用扫描统一使用 `ProjectStore._collect_asset_ids` 的收集规则（与清理同一规则），覆盖 T3 局部编辑节点（`original_asset_id` / `reference_asset_ids` / `localEditInputRoles` 内嵌引用）等全部真实引用字段。
- 生成结果节点的全部图片被删除时回退到无结果状态（复用 `_reset_deleted_original_owner_state`）。
- 资源库删除不提供撤销；这是用户确认引用警告后的显式终态操作。
- 边界补充（ADR 0016 / D3，2026-09-08）：**系统发起**的回收（生成失败/取消/超时的孤儿媒体、节点删除后无引用的级联归档）默认进回收区（7 天可恢复）；**用户主动**的资源库删除维持硬删。
