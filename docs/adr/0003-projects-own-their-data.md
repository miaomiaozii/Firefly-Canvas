# 项目是自包含的数据归属边界

萤火画布不再把项目视为画布的分类标签。一个项目只拥有一张核心画布，并使用独立项目目录保存项目元数据、该画布、媒体、预览和项目级资源；项目的复制、导出、删除与恢复都以整个项目为单位，禁止把删除项目的内容自动混入默认项目。

## Consequences

- 现有测试画布不迁移；萤火画布以空项目库开始，也不建设长期的经典画布格式导入器。
- 现有全局 `data/canvases/`、媒体目录和项目标签式结构需要迁移到项目目录。
- 所有需要持久化的创作数据必须声明项目归属，不能依赖当前打开项目等隐式全局状态。
- 系统不创建默认项目；首次启动必须新建或导入项目，所有项目内容写入都要求明确项目 ID。
- 程序代码默认位于 `D:\Firefly-Canvas`，项目库默认位于独立的 `D:\Firefly-Canvas-Projects`；项目数据不得写入 Git 仓库。
- 全局设置可以更换项目库位置；已有项目只能通过显式移动操作迁移，并在切换前校验文件完整性。
- 项目删除进入项目回收站；永久删除时才能清理其未被外部明确引用的文件。
- 项目导出必须能够包含恢复创作所需的完整项目数据。
- API Key、在线服务商、模型列表、主题和应用偏好保留为全局设置，不随项目导出。
- API Key 继续明文保存在全局 `API/.env`，不引入 Windows 系统密钥存储；该文件必须排除在 Git、项目复制和项目导出之外，界面只显示脱敏状态。
- 通用素材或提示词只有在用户明确保存到全局资源库时才跨项目存在；项目使用时默认复制进项目目录。
- 任何被画布使用的图片、视频或音频都必须成为项目媒体原件；远程 URL 和外部路径只保留为来源信息。
- 媒体导入采用后台任务和原子落盘，画布先显示导入状态；画布常态只加载缩略图，禁止把媒体二进制或 base64 写入画布 JSON。
- 项目内可按内容哈希去重，但去重不能让项目依赖其他项目的文件。
