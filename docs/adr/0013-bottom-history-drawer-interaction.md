# 生成历史使用避让缩略图的底部抽屉

核心画布的生成历史采用底部并排轨道：历史抽屉吸附视口底部，并在右侧为现有
画布缩略图导航保留独立空间。抽屉不覆盖顶部导航，不移动缩略图，也不使用遮挡
画布的居中弹窗。历史内容横向滚动，以尽量保留连续的画布工作区。

## Interaction contract

- 默认高度为 `240px`；短视口按 `floor(viewport height / 3)` 收窄。
- 用户调整高度的范围是 `160px` 到 `floor(viewport height / 3)`；折叠后高度为
  `46px`。
- 单击图片只选择。为了与双击区分，选择在双击判定窗口结束后提交。
- 同一图片的两次释放在 `320ms` 内且位置相距不超过 `20px` 时打开大图预览，
  并取消等待中的单击选择。
- 指针位移小于 `8px` 仍属于点击候选；达到 `8px` 立即进入拖动状态并取消选择
  与预览候选。
- 只有历史记录中的图片元素可以拖动。卡片、文字和操作区不得携带历史图片拖动
  数据，也不能在画布创建图片节点。
- 图片拖入画布只产生一次新图片节点；拖动过程不得先触发选择或预览。
- 正式行为测试应从抽屉与画布的可观察边界覆盖 PointerEvent 和 DragEvent，不能
  只检查 DOM 字符串或内部函数。

## Rejected layouts

- 不采用“全宽抽屉 + 上移缩略图”的上下分层方案：它会形成两层底部界面并持续
  占用更多垂直画布。
- 不采用把缩略图嵌入历史抽屉的整合工具坞：它会让生成历史与画布导航产生不必要
  的布局耦合，并压缩历史内容宽度。

## Validation

2026-07-21 在 Windows 10.0.26200、AMD64、CPython 3.10.11 和 Headless
Chrome 150.0.7871.129 上完成 Issue #4 的离线 UI 原型。原型嵌入现有
`smart-canvas.html` 页面，使用确定性内联图片，不读取 `.env`、应用数据或真实
API。完整 A/B/C 变体、单命令复现程序、机器可读事件轨迹、尺寸与遮挡断言、截图
以及 Standards/Spec 双轴审查保存在独立的
[`prototype/issue-4-history-drawer`](https://github.com/miaomiaozii/Firefly-Canvas/tree/6a590278accc7db961bb10e28679fa505f160ec8/prototypes/issue-4-history-drawer)
分支提交中，不并入产品代码。

浏览器在 1424×805 与 1008×673 两种实际内容视口下分别验证三个结构，共 6 次
运行、84 项断言，全部通过。805px 高视口的默认抽屉为 240px；673px 高视口按
三分之一上限收窄为 224px。六次运行都证明 6px 位移仍只选择，恰好 8px 即进入
拖动；单击、双击预览、PointerEvent 拖放与 DragEvent 拖放没有交叉误触；卡片
本身无法拖入画布。最终 Standards 与 Spec 复审均为 0 findings。

该证据接受的是上述布局与事件合同，不是原型实现。正式核心画布实现必须重写，
并使用项目生成原件与项目级生成历史。
