# #405 阶段 A：Codex CLI 0.162.0 原生 MCP 输出预算

**结论：Codex 在生成 `function_call_output` 时就会截断超预算的原生 MCP 工具结果，不是等到写 rollout 才截断。** 顶层 `tool_output_token_limit` 是可选的 token 预算覆盖项，不是固定上限。未配置时取有效模型目录的 `truncation_policy`：本版本内置目录为 **10,000 估算 token**，找不到模型元数据时的后备值则是 **10,000 UTF-8 字节**。指定工具可用 `[mcp_servers.<server>.tools.<tool>].output_token_limit` 优先覆盖。原生 MCP 格式化时三者均有 **20% 序列化余量**；既有实测不能判定当时用了哪一档。

本文只核对阶段 A 的一手源码和历史证据。不改 Codex 配置、Firefly 产品、schema 或提示词，不重跑模型，也不据此关闭 #405。

## 2. 默认值、单位与配置优先级

| 控制项 | 该版本的行为 |
|---|---|
| 最高优先级：`[mcp_servers.<server>.tools.<tool>].output_token_limit` | 可选正整数（最小 1），是加 20% 之前的 token 数。按该次调用捕获的有效 server 配置和 MCP 原始工具名查找；有值即用 `TruncationPolicy::Tokens`，不是与顶层预算取最小，也不受后备字节默认值封顶。插件策略合并时可另行收紧显式工具预算（S02、S06、S14）。 |
| 顶层 `config.toml`：`tool_output_token_limit` | schema 为非负整数，Rust 字段是 `Option<usize>`，未设置没有独立数值默认。它覆盖模型策略的预算而保留计量模式：原模式为 `tokens` 就直接用设置值，原模式为 `bytes` 就按 **4 UTF-8 字节/token** 转为字节预算；`0` 不是不限量（S03、S04、S08）。 |
| 未覆盖：有效模型的 `truncation_policy` | 内置 `models.json` 全部 11 条是 `{ "mode": "tokens", "limit": 10000 }`，如 `gpt-5.5`。有效条目也可能来自远端目录（含匹配缓存）或启动时 `model_catalog_json`，并非所有相同版本的会话都用内置值。未匹配到模型元数据才构造 `Bytes(10_000)` 后备策略（S04、S05）。 |

格式化调用的是 `with_serialization_allowance(policy)`，即在原单位上乘 `1.2` 向上取整。例如内置 10,000 token 的路径给文本 **12,000 估算 token**（约 48,000 UTF-8 字节）的预算；后备 10,000 字节的路径给 **12,000 UTF-8 字节**预算。`Wall time` / `Output:` 头先加入后再做预算；token 估算为 `ceil(UTF-8 字节数 / 4)`，不是服务端 tokenizer 或实际计费量。超限文本保留 UTF-8 边界上的首尾，中间加 `…N tokens truncated…` 或 `…N chars truncated…`；后者的 `N` 是省略字符数，预算仍按字节。截断标记、JSON 转义和媒体意味着它不是最终 wire JSON 的硬字节上限（S07、S08）。

## 3. 从 MCP 回包到模型输入及 rollout

1. **执行与展示分流。** `McpHandler` 先选择上述预算，再执行 MCP 调用。服务结果可经结果回调和模型输入模态处理；完成事件拿单独裁剪的预览，但返回给 `McpToolOutput` 的是未被这一事件预算裁剪的结果（S06）。
2. **生成 `function_call_output`。** `McpToolOutput::to_response_item` 调用 `response_payload()`：`CallToolResult` 先转为 payload，有加密块则保留 content items；否则非 `null` 的 `structuredContent` 优先序列化成文本，没有时使用转换后的 content items。加耗时头后，`truncate_function_output_payload` 对文本或内容数组做预算，然后生成 `ResponseInputItem::FunctionCallOutput` → `ResponseItem::FunctionCallOutput`（S07、S08）。对数组，文本与音频共享余额：文本超限截中间，音频按估算成本整块保留或省略；图片和加密块不扣这个预算。模态不支持时，图片/音频还可能更早被替换成省略说明（S06、S08）。
3. **记录并发送。** 工具结果封装时同时保存含余量的 `history_truncation_token_limit`（字节模式在此折算成估算 token）。上下文历史在副本上按保存的预算再检查一次，不重复加 20%；下一次采样请求从该历史生成；续跑也沿用已记录的历史预算（S09、S13）。rollout 保留的是已经过第 2 步格式化的 `response_item`，不是历史副本，也不是 MCP 完成事件的预览（S09、S10）。因此 rollout 中有截断标记与这条路径相符，但 rollout 本身不是发给模型的请求抓包。

### 不应与此预算混用的限制

- **事件与日志单独限额。** MCP 完成事件的结果预览设 **1 MiB**；分页历史的 `ItemCompleted` / `McpToolCall` 事件落盘使用 **64 KiB** 预览。两者都不限制 `response_item.function_call_output`。`codex.tool_result` 日志的 schema 默认 **2,048 UTF-8 字节**，且明确不影响模型可见输出（S06、S10、S11）。
- **`PostToolUse` 可替换或阻止结果。** 返回反馈时，普通工具响应会改用反馈文本，历史仍沿用原工具预算。上游 mock 用顶层 50、工具 100 验证了反馈按工具预算（含余量 120）截断（S13、S15）。
- **Code Mode 与传输也不是这条直接调用路径。** MCP 工具给 Code Mode 的嵌套结果不走这次 `response_payload` 裁剪；Code Mode 自己的外层输出有预算。stdio 的 **8 MiB/行**是超限关闭传输，不是对已接收结果做模型文本截断，也不适用于本次 HTTP 回包（S12）。
- **同版本的上游 mock 测试可作交叉证据，本文没有运行。** 一例配置顶层 500，断言模型请求里的原生 MCP `function_call_output` 带 `tokens truncated`。另一例顶层仅 50，指定工具 30,000 时仍可在模型请求中保留 116,000 字节的 ASCII 内容，而 150,000 字节会截断。远端策略测试也验证了 `Bytes(10_000)` 可被 50-token 顶层配置改为 `Bytes(200)`。这些断言排除了原生 MCP 格式化固定停在 10,000 或 64 KiB 的解释（S13）。

## 4. 既有 Firefly 本地实测（非本轮重跑）

历史 HTTP 捕获均为 200，Firefly MCP `plan.import_excel` 单一 text block 可完整解码出 Excel 行 2–16 的 **15 项**。Campaign 的原始 host 完成事件与 Codex CLI 0.162.0 原生 rollout 按工具调用对照如下（E01、E02）：

| 历史调用 | Firefly host 唯一 ID 数 | Codex rollout `function_call_output` | 缺失行 |
|---|---:|---|---|
| Normal | 15 | 无独立的 native rollout 统计 | 未知 |
| Campaign 首次（host seq 14） | 15 | 有截断标记，13 个可见 ID，9,844 字符 | 6、7 |
| Campaign 第二次（host seq 24） | 15 | 有截断标记，12 个可见 ID，9,828 字符 | 6、7、8 |

**9,844 / 9,828 是历史脚本对 rollout 文本项拼接后取 `len` 的字符数，不是 UTF-8 字节、token 或配置值。** 另记的 11,078 / 11,085 是 Firefly 封存副本脱敏后的字符数，也不能用于反推预算。私有原件已按既有流程清理，保留的摘要记录标记是否存在、缺失行和行哈希，不提供标记原文或当时生效的预算。实测只证明完整回包之后、进入 Codex 原生 rollout 时已丢失部分 ID；源码独立证明这一版本的截断位置与配置机制。证据文件的 `task_id` 脱敏修复不解释原生截断；不据此断言该次使用 10,000 token、10,000 字节或某个覆盖值，也不把 13/12 项当完整结果。
